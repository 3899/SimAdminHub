# 版本更新记录

### 📌 v0.0.4

#### ✨ 新增功能

- 新增 32 位 ARM（armv7）架构适配支持，一键安装脚本与在线更新助手可自动识别多类 armv7 架构标识并完成对应安装与更新，覆盖更多设备环境。
- 子设备与直连设备面板全面适配 VoLTE 能力，新增独立 VoLTE 诊断与管控页签，支持远程查看及管控子设备 VoLTE 状态。
- 直连设备 SIM 卡页面新增 VoLTE 快捷控制卡片与功能开关，支持一键启停 VoLTE 服务及 VoLTE 短信，触发自动重连。
- 后端开放 VoLTE 相关接口、设备设置与解绑接口的路由白名单，支撑上层功能调用。
- 新增子设备原生后台一键跳转能力，在设备列表、设备详情侧窗、子设备完整面板三处设置功能入口，支持局域网环境下跳转至设备原生 Web 管理页面；宿主机直连硬件场景下自动禁用该功能并同步提示。
- 新增子设备管理 IP 展示，在设备详情侧窗的设备信息分组中显示局域网管理 IP，支持一键复制；后端自动提取多类网络地址，离线与直连场景均有对应兜底展示。

#### 🏗️ 架构优化

- 重构后端数据库核心实现，按认证、设备、Agent、指令、通知、短信、备份、自动化等职责解耦，提升可维护性与扩展性。

#### 💫 体验优化

- 优化完整设备面板加载与刷新策略，首屏渐进显示，数据分频刷新，避免重复请求叠加。
- 设备面板首个页签统一命名为「首页」，规范界面导航命名。
- 优化 VoLTE 与 WiFi Calling 就绪状态判定与徽章显示逻辑，前后端统一多维度状态推断，解决徽章显示滞后、状态判定异常问题。
- 统一功能入口图标样式，站内设备面板跳转采用仪表盘样式主题图标，外部原生后台跳转采用外链样式图标，明确区分站内与外部跳转入口，避免视觉混淆。

#### 🐞 Bug 修复

- 修复本机设备完整面板请求链路过长导致加载缓慢或超时的问题，改为 Hub 回环直达 Device Service。
- 修复 Hub 重启后本机设备接入方式回落为网络接入的问题；同机已有 SimAdmin 时不再启动第二套 Device Service，避免蜂窝硬件争用。
- 修复 Bark 等通知渠道密钥保存后界面显示空白的问题，密钥配置完整保留，输入框以掩码形式正常显示，新增占位提示明确留空沿用规则。
- 修复 Hub 转发子设备设备状态定时报表时，模板解析异常导致通知内容为空的问题，优化报表结构解析逻辑，按分类完整展示设备状态信息。
- 修复设备重启指令参数校验异常问题，支持携带延时参数，避免延时重启指令被错误拦截。

#### 📦 构建与发布

- 同步发布 armv7 架构安装包与容器镜像，满足多架构部署需求。

### 📌 v0.0.3

#### ✨ 新增功能

- 新增 Hub 在线更新功能，支持版本检查、架构匹配下载、进度展示、校验后一键安装重启。

#### 🏗️ 架构优化

- 重构设备运行架构，抽取共享 runtime 统一底层能力，新增三轴能力模型与多设备隔离机制。
- 优化 eSIM 与 WiFi Calling 实现链路，新增动态能力检测、APDU 互斥、按设备隔离 Worker 等机制。
- 优化后端选择策略、短信幂等机制与 Worker 启动校验，提升多设备场景稳定性。
- 新增本机 Device Service，明确 Host Agent 能力边界，复用 SimAdmin 安装与运行逻辑。
- 新增最小权限更新助手，双重校验资产与文件清单，拦截非法下载与不完整包，保障更新安全。

#### 💫 体验优化

- 优化设备授权与添加入流，区分本机/宿主机直连标识，离线场景保留状态查看。
- 本机蜂窝设备的接入方式统一显示为「本机设备」，与宿主机外接模组的「宿主机直连」明确区分。
- 添加设备候选补充设备形态、管理方式和能力摘要。
- 直连设备 SIM 页新增 WiFi Calling 动态开关与状态徽章。

#### 🐞 Bug 修复

- 修复标准版设备面板持续请求 WiFi Calling 接口并报错的问题，根据设备能力动态判断是否发起请求，消除无效错误提示。
- 修复设备能力误判、接入方式显示错误、设备丢失无法恢复等多个直连场景问题。

### 📌 v0.0.2

#### ✨ 新增功能

- 新增可选单管理员登录保护功能，支持首次设置密码、账号登录、修改密码、主动登出，可配置会话有效期、浏览器空闲自动超时退出规则。
- 系统设置新增独立「安全」选项卡，集中管理密码策略与会话相关配置；启用密码保护后，顶部状态栏新增快捷退出登录入口。
- 提供本机命令行恢复能力，新增 `auth reset-password`、`auth clear` 指令，可在 Hub 服务器本地执行，用于忘记密码场景下重置或清空管理员密码。
- WiFi Calling 模块新增全量状态上报能力，运行状态可精准追踪全链路节点。
- Hub 子设备面板新增动态「WiFi Calling」页签，支持远程查看与控制子设备的 WiFi Calling 功能，集中管控能力进一步完善。
- VoLTE 预留状态字段和徽章渲染入口，只有未来上报 `ready` 时才显示，不再根据静态能力误显示。

#### 🏗️ 架构优化

- 复用 SimAdmin 认证鉴权、登录、安全配置、通知通用组件，划分不同接口权限边界，代码统一维护。
- 优化事件上报机制：SimAdmin 侧新短信与通知事件入库后立即唤醒 Agent 并上报；同时保留轮询作为兜底机制。
- 抽取共享 WiFi Calling 状态 Hook，SimAdmin 与 Hub 使用同一套功能启用状态逻辑，减少重复代码，统一状态判定标准。
- HUB 子设备面板复用 SimAdmin 的 SIM 卡和 WiFi Calling 页面，通过 Hub 适配层接入指定设备，避免维护两套功能实现。
- 明确自动化调度权责归属与执行边界，Hub 侧调度规则不再同步到子设备，仅离线兜底时子设备执行本地规则。

#### 💫 体验优化

- 精简 Hub 链路状态展示维度，仅保留设备硬件、控制通道、SIM 卡、蜂窝注册四项核心状态；主动关闭蜂窝数据不再计入「需处理」状态，状态判定更贴合实际使用场景。
- 优化 WiFi Calling 徽章展示规则：仅在状态就绪时显示徽章；设备列表徽章统一放置在设备列表「运营商 / 网络」列内。
- 添加设备时「一键接入」功能新增进度加载状态与提示；自动发现设备接入时不再修改手动地址输入框内容，操作交互更友好。
- HUB 系统设置页面服务状态改为卡片形式展示，优化视觉呈现。
- 通知通道错误统一中文反馈，补充企业微信 IP 异常处理指引，错误信息自动脱敏。

#### 🐞 Bug 修复

- 修复 Hub 控制子设备「数据连接」开关时未同步的问题。
- 修复 WiFi Calling API 绕过 Hub 适配层的问题，确保完整设备面板中的请求通过当前设备通道执行。
- 修复企业微信应用与 Telegram 的 API 反代地址留空时生成无效请求地址的问题，未配置反代时自动直连官方 API。

#### 📚 文档更新

- Docker 部署默认调整为 host 网络模式，移除端口映射；Hub 直接监听宿主机 `3001` 端口，使容器可正常接收局域网 mDNS 组播，实现设备自动发现。
- 同步更新 README、安装指南、使用指南、安全说明文档，保持文档说明与功能同步。

### 📌 v0.0.1

#### ✨ 新增功能

- 上线 SimAdminHub 集中管理控制台，支持统一查看和管理多台 SimAdmin 设备及宿主机直连蜂窝模组。
- 支持局域网 mDNS 自动发现、设备地址接入、SimAdmin 设备端主动连接，以及自动授权和人工确认两种准入方式。
- 新增设备总览与设备管理，集中展示在线状态、运营商、网络制式、信号、温度、运行时长、接入方式和链路状态，并支持分组与标签管理。
- 新增设备详情侧窗，提供状态、SIM 卡、设备信息、系统资源、快捷功能和重启控制。
- 集成 SimAdmin 完整设备面板，支持状态、SIM 卡、动态 eSIM、蜂窝网络、设备网络、备份与恢复、设备设置及设备本地 OTA。
- 上线集中短信中心，设备首次接入时执行历史短信全量同步，后续增量同步；支持按设备和会话查看、跨设备搜索、发送短信及批量删除。
- 上线集中通知中心，支持多通知通道、转发规则、设备范围、免打扰、发送测试、投递日志和失败重试队列。
- 上线集中自动化中心，支持按全部设备、多个分组或指定设备执行重启基带、重启设备和发送短信任务，并记录逐设备执行结果。
- 新增系统设置，提供运行概况、设备连接策略、自动或人工授权、Host Agent 开关、存储统计、数据保留、手动清理、自动备份及组件化备份恢复。
- 新增版本检查、Hub 重启、敏感信息全局显隐和 Prometheus 指标能力。

#### 🏗️ 架构设计

- 后端采用 Rust、Axum 与 SQLite，前端采用 React、Vite 与 Material UI，Hub 业务数据统一按设备 ID 隔离。
- 建立 Agent 注册、Bearer 认证、WebSocket 心跳、断线重连、逐项 ACK、outbox 和命令账本机制，保证连接与命令执行状态可追踪。
- SimAdmin 内置 Agent 在单设备模式下保持沉寂，切换集中管理模式后连接 Hub；设备本地数据与 Hub 集中数据相互独立。
- Host Agent 保持为独立服务进程，用于管理无法安装 SimAdmin 的 USB/PCIe 蜂窝模组；默认安装但不启用，不创建常驻进程。
- 复用 SimAdmin 的通知、自动化和完整设备面板前端组件，通过 Hub 适配层接入集中 API，避免维护两套交互实现。
- 支持设备重连复用原有身份、USB 端口变化识别、硬件绑定、物理槽位绑定和身份冲突确认。
- 网络与宿主机自动发现改为添加设备窗口按需启停，并使用短租约处理浏览器异常关闭；Host Agent 新增 `/dev/serial/by-id`、ModemManager 全量枚举和只读 AT/IMEI 探测。

#### 💫 体验设计

- 管理框架与 SimAdmin 保持一致，支持侧边栏展开和收起、顶部状态栏、全局敏感信息显隐及统一版权版本信息。
- 总览设备卡片按行保持等高；离线设备仅保留设备名称和离线状态，其余实时信息使用灰色占位，避免缓存数据造成在线误判。
- 设备列表为离线设备统一使用灰色占位图标、文本和链路状态，不继续展示离线前的运营商、信号、温度、运行时长等数据。
- 短信中心采用设备列表、会话列表和消息内容三级布局，接收与发送消息分别左右对齐，并支持会话级和消息级批量选择。
- 通知与自动化中心沿用 SimAdmin 的布局、卡片、弹窗和模板变量，仅增加 Hub 所需的设备范围配置。
- 系统设置采用多选项卡布局，统一UI与操作反馈。

#### 📦 构建与部署

- 提供 `simadminhub-x86_64.tar.gz` 和 `simadminhub-aarch64.tar.gz` 两种固定名称的 Linux 发布包，归档同时包含 Hub 与 Host Agent。
- 提供 `install.sh` 一键安装和升级脚本，支持自动识别架构、指定版本、国内下载加速和失败回退。
- 提供 `uninstall.sh` 一键卸载脚本，默认保留配置与数据，使用 `--purge` 时执行彻底清理。
- 提供 `x86_64` 与 `aarch64` 多架构 Docker 镜像，默认映射 `3001:3001` 并预先授予 Host Agent 所需硬件访问权限。

#### ⚠️ 当前限制

- 当前版本为单用户控制台，不提供 Web 登录、用户、角色或租户；必须部署在受信任网络中，不应直接暴露到公网。
- Hub 顶层集中 OTA 暂未开放；SimAdmin 子设备完整面板仍保留设备本地 OTA。
- 日志中心暂未开放，服务与诊断日志仅输出到标准输出或系统服务日志。
- Host Agent 仅支持 Linux，实际能力取决于宿主机、蜂窝模组以及 Direct AT、QMI、MBIM 或 ModemManager 后端支持情况。
- 备份页面暂不支持上传外部备份文件，跨主机灾备恢复需要按照安装文档手动执行。
- 首个稳定版本发布前，Agent 协议、API 和数据库结构仍可能调整。
