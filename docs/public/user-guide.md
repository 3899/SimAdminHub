# 使用指南

本文面向 SimAdminHub 日常使用者，说明当前已经开放的页面、数据关系和常见业务规则。

## 使用前提

所有网络接入的子设备都应运行最新版 SimAdmin。Hub 依赖 SimAdmin 内置的 Hub Agent、接入接口和通信协议；旧版可能提示“请求的接口不存在”或始终无法上线。安装或升级 SimAdminHub 后，应先更新子设备，再进行自动发现或地址接入。

## 页面导航

| 页面 | 用途 |
| --- | --- |
| 总览 | 查看设备数量、设备卡片、信号、温度和链路状态 |
| 设备 | 检索、筛选、分组、标签、编辑、删除和进入完整设备面板 |
| 短信 | 按设备和会话查看、搜索、发送及批量删除短信 |
| 通知 | 管理转发日志、转发规则、转发通道和失败重试 |
| 自动化 | 管理自动化任务、设备范围、手动运行和执行日志 |
| 系统设置 | 管理连接参数、数据保留、存储、备份恢复和版本检查 |

## 总览

总览中的每张设备卡片显示：

- 设备名称、运营商和网络制式。
- 手机号、信号百分比和 dBm。
- 接入方式、运行时长和最低/最高温度。
- 硬件、控制、SIM、蜂窝注册和数据连接等链路状态。

点击设备卡片会打开设备上下文侧窗，点击页面空白区域或关闭按钮可收起。侧窗的状态页汇总 SIM 卡、设备信息和系统资源；功能页提供完整面板、同步、查看短信、发送短信、重启基带和重启设备。

## 设备

设备列表支持按名称、IMEI、状态、分组、标签和接入方式筛选。列表展示设备与 IMEI、分组与标签、接入方式、链路状态、手机号、运营商与网络、信号、最高温、运行时长、版本和最近上报时间。

### 接入方式

- **网络接入**：设备已安装 SimAdmin，由内置 Agent 执行操作。
- **宿主机本地接入**：模组连接在运行 Host Agent 的宿主机上，由 Host Agent 执行其支持的操作。

自动发现按需运行：打开“添加设备”时，Hub 才开始局域网 mDNS 浏览并要求 Host Agent 枚举新模组；关闭窗口后自动停止。已经接入的设备仍会继续上报状态和执行命令。Host Agent 会优先识别稳定的 `/dev/serial/by-id` 路径，并结合 ModemManager 全量枚举和只读 AT 探测判断控制端点。当前版本不提供手动填写宿主机串口路径，自动发现不到时请检查容器或服务的硬件权限以及宿主机驱动。

### 设备状态

- **在线**：Agent 连接有效，设备可以正常上报和接收支持的命令。
- **离线**：超过离线阈值没有心跳，或 Host Agent 已无法访问对应模组。
- **身份待确认**：检测到同一身份的并发所有者、槽位更换硬件或硬件指纹冲突，需要用户核对设备和绑定关系。

局部能力异常不会简单显示成含义模糊的“降级”。设备仍在线时，具体异常会显示在硬件、控制、SIM、蜂窝注册和数据连接等链路层级中。

身份待确认期间，除解除绑定外的控制操作会被阻止。请核对 IMEI、硬件指纹、USB 槽位和当前 Agent，再确认正确设备。

### 分组与标签

分组和标签用于：

- 整理和筛选设备。
- 指定通知规则作用范围。
- 指定自动化任务作用范围。

它们不代表客户、租户或权限边界，也不会把设备数据混合保存。

### 完整设备面板

SimAdmin 网络设备当前提供状态、SIM 卡、动态 eSIM、蜂窝网络、设备网络、备份与恢复、设备设置和 OTA 页签。OTA 支持设备本地在线更新和上传更新包；设备是否显示 eSIM 等动态功能取决于实际能力。

Host Agent 设备只显示宿主机和模组实际支持的功能，不会为了界面完整而显示不可执行操作。

### 删除设备

删除在线 SimAdmin 设备时，Hub 会自动通知设备解除绑定，成功后再删除 Hub 中的设备和集中数据，不需要先登录设备操作。

解除失败或超时时，Hub 会保留设备并显示错误。离线设备无法接收解除命令，Hub 会直接删除本地记录；设备以后重新连接时需要重新接入。

## 短信

短信页面由设备列表、会话列表和消息内容三部分组成：

- 设备列表顶部的“全部设备”用于跨设备搜索。
- 选择具体设备后，可以查看该设备的会话和收发统计。
- 接收短信靠左显示，发送短信靠右显示。
- 支持新建对话、搜索、选择整个会话、选择单条短信、全选和批量删除。

设备第一次连接某个 Hub 时，会将本地历史短信完整同步一份。以后连接同一个 Hub 只同步新增和变化数据；切换到另一个 Hub 后会重新执行一次完整同步。

设备数据库和 Hub 数据库相互独立。在 Hub 删除短信不会删除设备本地短信，在设备删除也不会自动删除 Hub 中已经保存的副本。

## 通知

通知中心包含：

- **转发日志**：查看规则、通道、来源设备和投递结果。
- **转发规则**：按事件、条件和设备范围决定是否通知。
- **转发通道**：配置 Webhook、Bark、PushPlus、企业微信、钉钉、飞书、Telegram、电子邮件和 Server酱等通道。
- **失败重试**：查看异步投递失败原因，手动重试或删除队列项。

设备范围支持全部设备、多个分组或多台指定设备。

Hub 和设备本地的通知配置相互独立：

1. Hub 有启用规则命中事件并进入可用通道时，由 Hub 负责发送，设备不重复通知。
2. 没有 Hub 规则接管时，如果设备允许本地兜底，则使用设备自己的通知配置。
3. Hub 已接管但通道发送失败时，由 Hub 重试，不再让设备重复发送。

发送测试后，页面会显示成功或失败结果。通道密钥保存后不会再次明文返回。

## 自动化

自动化任务可以作用于全部设备、多个分组或多台指定设备。当前支持：

- 重启基带。
- 重启设备。
- 发送短信，短信内容可插入时间和随机字符串变量。

新建任务默认启用，Hub 任务始终由 Hub 集中调度，不会复制到设备。SimAdmin 设备自己的自动化规则保持独立，并由设备端“Hub 离线时使用设备本地规则”开关控制离线接管。

每个任务卡片显示设备范围。发送短信任务还会显示收件号码和短信内容。运行日志记录每台目标设备的执行结果。

设备备份不属于 Hub 自动化动作。需要备份某台设备时，应进入该设备的完整面板，在设备自己的“备份与恢复”中执行。

## 敏感信息

顶部状态栏的全局按钮控制以下信息是否明文显示：

- ICCID。
- 设备手机号。
- 短信中心号码。
- IMEI。

默认模糊隐藏。短信会话中的联系人号码不受该开关影响，避免无法识别会话。

该功能只是页面显示保护，不能替代访问认证。Hub 数据库中仍保存业务所需的原始值。

## 系统设置

### 概览

概览显示 Hub 版本、架构、运行状态、存储占用和数据路径。完整 systemd 安装和标准 Docker 安装都会显示“本机 Host Agent”开关：默认关闭且不启动 Host Agent 进程；只有需要管理与 Hub 同机直连的蜂窝模组时才启用。仅安装 Hub 或直接运行单个二进制时，该开关不可用；标准 Docker 安装已经预授予所需硬件访问权限。

### 连接设置

默认每 30 秒心跳一次，90 秒未收到心跳后判断离线。心跳间隔可设置为 5 至 300 秒，离线时间至少为心跳间隔的两倍，最大 1800 秒。

设备授权可以选择自动授权或人工确认。修改心跳设置后，现有 Agent 会重新连接并获取新配置。

### 数据保留

默认策略：

| 数据 | 保留时间 | 每设备最多记录 | 默认启用 |
| --- | ---: | ---: | --- |
| 短信 | 365 天 | 不限制 | 否 |
| 通知日志 | 180 天 | 10000 | 是 |
| 自动化日志 | 180 天 | 5000 | 是 |
| 命令历史 | 90 天 | 5000 | 是 |

保存规则不会立即清空全部历史。后台维护会定期执行，也可以在系统设置中手动清理指定组件或优化数据库。

### Hub 备份与恢复

Hub 备份可以选择：

- Hub 配置。
- 设备与分组。
- 短信。
- 通知配置和通知记录。
- 自动化配置和自动化记录。
- 命令历史。

自动备份默认关闭。启用后的默认计划为每天 `02:00`，最多保留 10 份。

恢复前系统会检查文件哈希、数据库完整性和版本兼容性，并显示可恢复组件。组件恢复采用合并方式，未选择的数据保持不变。恢复设备信息后，在线状态会等待 Agent 实际重连后重新建立。

Hub 备份只包含 Hub 自己的数据，不会远程备份每台设备的本地数据库。当前页面只能恢复本机备份目录中已经登记的备份，不支持上传下载到其他位置的备份文件；用于整机灾备时应选择全部组件，并按[安装与部署](install.md)中的人工恢复步骤操作。
